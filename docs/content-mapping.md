# 内容映射与降级规则

当前只接受 Notion 官方 `HTML` 导出 ZIP 或解压目录。`Markdown & CSV` 会在钉钉写入前明确拒绝，因为该格式不能可靠表达三图并排、图片与表格同排等布局。

转换继续复用 Pandoc；项目只增加一个小型 Lua Filter：把 Notion 的单图 `<figure class="image">` 改为普通图片段落，把真正的多列 `column-list` / `column` 和相对列宽变成 DOCX 无边框布局表，并移除 `to-do-list` 被 Pandoc 误加的普通圆点层。最小 OOXML 整理继续保证列宽、图片尺寸和页面宽度一致。

- [Notion：Export your content](https://www.notion.com/help/export-your-content)
- [Pandoc User’s Guide](https://pandoc.org/MANUAL.html)

## 页面与子页面

- 自动扫描 HTML 本地链接，推断唯一根页面。
- 标题优先读取根页面的 `page-title`，其次读取 `<title>`，最后才使用去掉 Notion 页面 ID 的文件名。
- 根页面标题只传给钉钉作为在线文档名称；组合 HTML 不再携带会生成 Word `Title` 段落的 `<title>`，根页 `page-title` 或与根标题同名的首个 `<h1>` 也不会重复进入正文。
- 按链接顺序递归收集可达子页面，循环和重复链接只处理一次，并追加到同一篇目标文档。
- 转换时记录每个子页面入口的可见文字、源页面、目标页面序号和目标标题；导入后读取真实钉钉 H2 块 ID，把第一个独立入口块替换为一个原生 `toc`，其余已被目录覆盖的独立入口块精确删除。
- 目录内容显式写入且只包含追加子页面：每项的 `text` 等于子页面标题、`anchorId` 等于对应 H2 UUID、`level=2`。入口块或标题无法按数量和顺序唯一对账时停止修改，不猜测目标，也不删除包含其他正文的块。
- 上述行为是默认 `inline` 模式。可选 `tree` 模式为每个页面创建同名容器文件夹和同名独立文档，随后把 HTML 子页面入口原位更新为真实钉钉文档 URL；创建前先解析目标节点归属，Workspace 文件夹走 Wiki，真正的钉盘文件夹才走 Drive。
- 树模式以第一次遍历关系作为物理父级；同一页面从其他位置再次出现时只保留链接。循环和重复引用不会重复创建远端文档。
- 多个独立根页面无法唯一推断时，要求显式传入 `--entry`；链接指向的 HTML 缺失时立即失败。

## 图片

- 根页面 `<img class="page-cover-image">` 单独识别为封面，不再作为正文图片写进 DOCX；文档导入完成后使用钉钉原生封面资源能力上传，并通过文档样式回读确认。`tree` 模式下每个独立页面分别执行相同流程。
- 正文和 Figure 中的 HTTP(S) 外部图片仍会被拒绝；Notion 书签卡片中未随导出包提供的外部站点图标或缩略图会被省略，同时保留书签链接和文字并输出显式降级警告。data URI、绝对路径和越界路径一律拒绝。
- 对每个本地图片记录相对路径、MIME、字节数、引用次数和 SHA-256。
- 相同 SHA-256 在准备目录只复制一份，但 HTML 中的每个图片位置都会进入 DOCX。
- 图片总体积可能触发钉钉导入上限时，只在工具临时目录中把较大的 PNG 以 JPEG 质量 92 重新编码；源 ZIP/目录保持不变，并分别记录源文件和本地化文件的大小、MIME 与 SHA-256。
- DOCX 同时检查媒体数、图片关系数、图片实际出现次数、外部图片关系和 Notion 临时 URL。
- Notion 普通单图不使用 Pandoc 默认的 Word Figure 实现，避免每张图片被额外包装为 1×1 表格；有图注时图片和图注改为相邻的可编辑段落。
- 列内图片会按相对列宽缩小，禁止宽度超过所在布局单元格。

## 布局与特殊结构

| HTML 源结构 | DOCX / 钉钉映射 | 报告状态 |
| --- | --- | --- |
| 根页面标题 | 仅作为钉钉文档标题；DOCX 正文中的重复 `Title` / 同名 `Heading1` 均为 0 | `preserved` |
| 根页面封面 `page-cover-image` | 从 DOCX 正文移除，导入后设置为钉钉原生文档封面并回读样式确认 | `preserved` |
| 子页面入口链接 | 导入后合并成一个钉钉原生“子页面”目录；目录只含追加子页面的 H2 标题和精确锚点 | `preserved` |
| 递归文档树 | 每页一个同名文件夹和同名文档；入口链接回填为对应钉钉文档 URL | `preserved` |
| 单图 `<figure class="image">` | 普通图片段落，不生成 Pandoc 的 1×1 Figure 表 | `preserved` |
| 单列 `column-list` / `column` | 直接输出列内块，不生成 1×1 布局表 | `preserved` |
| 两列及以上 `column-list` / `column` | DOCX 中用无边框布局表保留结构；导入后原位恢复为钉钉原生分栏 `sr:true` | `preserved` |
| 三张图片并排 | 三单元格同一布局行，每格一张内嵌图片 | `preserved` |
| 图片与表格同排 | 两个或多个同排单元格，表格保持为嵌套数据表 | `preserved` |
| 普通 HTML 表格 | 可编辑数据表格 | `preserved` |
| Notion 书签卡片 | 保留链接和文字；未打包的外部站点图标/缩略图不联网下载并明确省略 | `preserved` / `degraded` |
| `to-do-list` / checkbox | DOCX 保留无圆点的 `☐/☒` 和完成状态；导入后用钉钉官方 JSONML 块能力恢复为原生可点击待办并回读核对 | `preserved` |
| `<pre><code>` / `<pre>` | DOCX 保留 `SourceCode` 段落；导入后按源文本和顺序原位更新为钉钉原生 `code` 块，保留换行、缩进及可识别语言并回读核对 | `preserved` |
| Callout | 保留文本内容，背景等装饰样式不作完全保真承诺 | `mapped` |
| Toggle | 保留展开内容，不保留折叠交互 | `degraded` |
| 数据库 CSV 链接 | 记录文件哈希和降级警告，不自动嵌入数据库视图 | `degraded` |
| 普通附件 | 保留链接，附件内容暂不自动上传 | 显式降级 |

包含多栏时使用横向 DOCX 页面和 10 英寸正文宽度，减少图片、表格在窄列中重叠或裁切。写入前记录全部布局表和真实数据表的顺序、列数；导入后以保留下来的 `Notion Columns` 专用样式识别布局表，并核对布局表数量和列数，再设置钉钉原生 `sr:true` 分栏并移除表格/单元格边框属性。普通数据表即使被钉钉导入器降级成非表格块，也不影响分栏识别，更不会参与更新。最终仍以钉钉真实导入后的人工打开结果作为布局验收终点。

## 固定回归夹具

- 普通 HTML：标题、正文、列表、表格、代码块、链接和两张 PNG。
- 长篇 HTML：30 节，并检查开头、中间和末尾唯一标记。
- 多图片 HTML：8 个引用、2 个唯一内容哈希，验证去重后仍保留 8 个输出位置。
- 单图 HTML：普通 Figure 与单列容器各一张图；验收两张图都存在、DOCX 表格数为 0、页面保持纵向。
- 子页面与特殊块 HTML：两层子页面、中文路径、URL 编码、Callout、Toggle、CSV 和两张图片；同时验收一个含子/孙页面两项的原生目录、旧入口删除，以及写入未知后的原文档恢复。
- 同一子页面夹具还验收递归模式创建三级文件夹与三篇独立文档、回填两个跨文档链接、普通 Drive 与 Wiki 两类目标，以及相同任务复跑零新增。
- 多栏 HTML：一行三张图片，以及一行 40% 图片 + 60% 表格；验收布局表数量、列数、列宽、边框、图片宽度和横向页面，并确认列内图片不再嵌套 1×1 Figure 表；fake dws 还必须模拟普通数据表未被回读和 Word 遗留 `list.start=0`，确认两个专用样式布局表恢复为 `sr:true`、普通数据表不更新，以及状态未知后只恢复原文档。
- 待办 HTML：一条已完成、一条未完成；验收 DOCX 中方框状态、普通圆点为 0，并验收钉钉原生 `isTaskList/isChecked` 块更新与回读。
- 代码块 HTML：三段单行/多行代码与三种语言；验收 DOCX `SourceCode` 数量、原生 `code` 块更新、正文/语言回读，以及更新状态未知后的原文档恢复。
- 标题去重：目录和 ZIP 输入都验收 DOCX `Title=0`、同名根 `Heading1=0`；子页面标题仍存在。
- 书签外部预览：验收链接与文字保留、外部站点图标/缩略图被计数并省略、DOCX 外部图片关系为 0；书签外的远程正文图片仍必须失败。
- 根页面封面：验收 DOCX 正文图片数为 0、封面暂存文件哈希和大小一致、原生封面设置后样式回读可确认，并验证写入回执未知但回读已存在时不会重复上传或重复导入。

运行 `npm run test:stage4` 会直接回归阶段 4 的上述内容、安装版一键界面、目录树外文件夹搜索、HTML-only 拒绝规则和永久清理。
